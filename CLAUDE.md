# Pocket Tetris

Тетрис в стиле карманной консоли для телефона (PWA). Чистый HTML/CSS/JS без сборки и без зависимостей.
Живой сайт: https://pocket-tetris.onrender.com (статический сайт на Render, собирается из корня репозитория, автодеплой при пуше в `main`).
Сервер: https://pocket-tetris-battle.onrender.com (веб-сервис на Render из `server/`, бесплатный тариф: засыпает без нагрузки и при этом теряет память, первое подключение до минуты).
GitHub Pages не используется (отвечает 404), `.nojekyll` остался с первой версии.

## Файлы

- `server/engine.js`: правила игры: фигуры, ходы, гравитация, очистка линий, очки, уровни, мусор в битве. Один файл для браузера (`window.PocketEngine`) и для Node (`require`), ES5.
  - Время идёт фиксированными тиками, 60 в секунду. Вся арифметика целочисленная: гравитация — таблица `GRAVITY` в 1/65536 ряда за тик, задержки в тиках. Только так партия пересчитывается одинаково в любом браузере и на сервере. Никаких `Math.pow`, дробного времени и зависимостей от экрана внутри движка.
  - API: `create(rules)` возвращает объект игры с `act(action)`, `garbage(n)`, `step()`, `takeEvents()`, `recording()`; `replay(rules, recording, maxTicks)`; `dailyRules(day)`; `modeRules(mode, opt, seed)` — правила MARATHON/40 LINES/TIME ATTACK/DIG, одни и те же для игры и сервера (по ним сервер переигрывает вызовы). Правила `dig: N` начинают поле с N рядов мусора (дырки по seed, в соседних рядах разные) и кончают игру `complete`, когда мусора не осталось.
  - Лежит в `server/`, чтобы любое изменение правил пересобирало и сервер (если у сервиса на Render корневая папка `server/`).
  - Изменение, после которого старые записи пересчитаются иначе, требует поднять `VERSION`: сервер отвечает 426 на записи другой версии.
- `index.html`: разметка консоли (экран, боковые панели, меню, меню паузы, лобби битвы, окно таблицы дня, кнопки), CSP в `<meta>`. Подключает `server/engine.js`, `puzzles.js`, `app.js`.
- `app.js`: интерфейс в одном IIFE, ES5 (`var`, `function`, без модулей). Разделы помечены `/* ---- name ---- */`: language, modes, puzzles, puzzle hints, daily challenge, console colors, pieces, palettes, state, HUD/storage, drawing, fit to screen, sound, game flow, share result, share card, daily top, challenges, progress on the server, online battle, pause menu, menu, input, swipe gestures, main loop, boot, install.
  - Идущая партия хранится в `game` (объект движка). Переменные `board`, `score`, `piece` и т. д. — её зеркало для отрисовки и HUD, обновляется в `pull()`.
  - После любого обращения к движку вызывается `afterEngine()`: зеркало, события (звуки, сообщения, конец игры в `onEngineEvent`), обновление HUD.
  - Главный цикл `tick` прогоняет столько тиков движка, сколько прошло времени.
- `style.css`: оформление; цвета консоли заданы CSS-переменными (`--shell`, `--btn`… и `--lcd-*`), `app.js` подменяет их для скинов и палитр экрана.
- `puzzles.js`: `window.POCKET_PUZZLES`, 40 уровней головоломок, 5 глав по 8 (`rows` сверху вниз, `#` = блок; `pieces` = очередь фигур; необязательный `tip` показывается при старте уровня; `hint` — одно решение: `H` = нажать HOLD, `T:x,y x,y x,y x,y` = клетки поля, куда ложится фигура). Файл целиком пишет генератор, руками не править.
- `tools/puzzlegen.js`: генератор и решатель головоломок (Node). Фигуры и кики берёт из `server/engine.js`.
  - `node tools/puzzlegen.js` сохраняет уровни, которые уже есть в `puzzles.js` (прогресс игроков хранится по индексу), дописывает недостающие по `PLAN`, заново проверяет все и перезаписывает `puzzles.js`.
  - Для каждого уровня ищет решение (сначала простые сбросы сверху и без HOLD) и пишет его в `hint`. С `--solutions file.json` дополнительно пишет нажатия этого же решения для браузерного теста.
  - Из-за бюджета времени на уровень результат может отличаться между машинами.
  - Две физики. `drop`: фигура только бросается сверху (главы 1–3). `full`: настоящие ходы игры в режиме головоломок, где фигура не падает сама: влево, вправо, вниз, повороты с киками, потом сброс. Это позволяет подсовывать фигуру под навес (главы 4–5).
- `server/server.js`: сервер на голом `http` (Node ≥ 18, без зависимостей).
  - Битвы: комнаты с 4-значным кодом хранятся в памяти (поэтому только один экземпляр). Вниз к игрокам идут Server-Sent Events, вверх POST с `text/plain` (без CORS preflight).
    - Разрешённые сообщения (`ready`, `lost`, `won`, `attack`, `board`) проверяются в `MESSAGES`, origin'ы лежат в `ALLOWED_ORIGINS`.
    - `attack` — не больше 5 рядов за раз и 12 за 4 секунды. `won` сервер пропускает, только если соперник молчит 15 с и больше.
    - Комната, в которую никто не вошёл, удаляется через 30 с. В остальном битва доверяет клиентам: подделать `lost` или умеренный мусор можно.
  - Таблица дня:
    - `POST /daily` `{pid, name, day, v, rec}`. Сервер прогоняет запись нажатий `rec` через `engine.js` и сам считает очки; присланному числу не верит. Хранится лучший результат игрока за день.
    - `GET /daily/YYYYMMDD?me=<pub>` возвращает топ-10, число игроков и место игрока.
    - При равном счёте выше тот, кто набрал его раньше.
  - Неделя: каждая отправка результата дня прибавляет к сумме недели (неделя названа датой своего понедельника) прирост лучшего результата этого дня. `GET /week/YYYYMMDD?me=<pub>`.
  - Вызовы: `POST /challenge {pid, name, mode, opt, seed, v, rec}` переигрывает запись по `modeRules` и создаёт вызов с id из 6 символов (живёт 2 недели, до 100 результатов); `GET /challenge/<id>?me=<pub>` — настройки и таблица; `POST /challenge/<id>/result {pid, name, v, rec}` — попытка друга, тоже переигрывается. В таблице выше тот, у кого больше очков, а в 40 LINES и DIG — кто быстрее финишировал (незаконченные ниже).
  - Прогресс: `POST /progress {pid, data}` (только для игроков с именем) и `POST /progress/load {pid}`; `data` — открытые цвета, решённые головоломки, потраченные подсказки, рекорды и серия дней, сервер пропускает только известные поля.
  - Имена и id:
    - `pid` — 16 hex-символов, хранится на устройстве и служит кодом восстановления. Везде в хранилище и в адресах используется `pub` = первые 16 hex SHA-256 от `pid`.
    - Имя принадлежит первому, кто его занял: `POST /name {pid, name}` возвращает 409, если имя занято. `GET /name/<pub>` отдаёт имя по коду восстановления.
  - Хранение: Upstash Redis через REST, если заданы `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`, иначе в памяти (стирается, когда сервер засыпает). Ключи: `pt:d2:<day>`, `pt:n2:<day>`, `pt:w2:<week>`, `pt:wn2:<week>`, `pt:owner:<NAME>`, `pt:handle:<pub>`, `pt:ch:<id>`, `pt:chr:<id>`, `pt:prog:<pub>`.
  - Лимиты за 10 минут:
    - с одного адреса — 10 комнат, 30 отправок результата, 10 смен имени;
    - с одного адреса ещё 20 вызовов/попыток и 30 сохранений прогресса;
    - на весь сервер — 600 отправок результата, 300 вызовов/попыток и 5000 игроков в день.
    - Адрес берётся из `CF-Connecting-IP` / `True-Client-IP` (их ставит Cloudflare перед Render), `X-Forwarded-For` только запасной вариант.
- `sw.js`: service worker, сначала сеть, кэш только для офлайна. Новый файл, который нужен офлайн, добавить в `CORE` и поднять `CACHE`.
- `manifest.json`, `icons/`: установка как приложение; `fonts/`: локальные шрифты Press Start 2P и JetBrains Mono (OFL).

## Игра

Режимы (`MODES`):
- MARATHON: выбор стартового уровня 0–9.
- 40 LINES: старт с уровня 2, уровень растёт каждые 10 линий.
- DIG (РАСКОПКИ): 10 рядов мусора, прокопаться до дна на время; скорость как в 40 LINES. Рекорд — время, как в 40 LINES (`raceMode()`).
- TIME ATTACK: 5, 7 или 10 минут.
- DAILY: 5 минут; фигуры по seed из даты по времени UTC+5, у всех одинаковые.
  - Лучшая партия дня хранится на устройстве как запись нажатий и уходит в таблицу дня, если у игрока есть имя; место показывается под результатом.
  - Кнопка DAILY TOP: список за день и ЗА НЕДЕЛЮ; MY NAME — имя и код восстановления; I HAVE A CODE — вернуть имя и прогресс на новом телефоне.
  - Серия дней (`pocket-tetris-streak` = {last, n}): сколько дней подряд игрок доиграл испытание дня; показывается от 2 дней под результатом и над таблицей.
- Вызов другу: у каждой партии MARATHON, 40 LINES, TIME ATTACK и DIG свой seed и запись нажатий. После неё кнопка ВЫЗОВ ДРУГУ создаёт вызов (нужно имя) и отправляет ссылку `?c=<id>`. Друг играет тем же seed, результат сразу уходит на сервер, и показывается таблица вызова. Пока идёт вызов, его хранит `challenge`; смена режима в меню или «В МЕНЮ» его сбрасывают.
- Прогресс уходит на сервер (`saveProgressSoon`, раз в 3 с после изменений) у игроков с именем. При восстановлении по коду `mergeProgress` объединяет цвета/головоломки/подсказки и берёт лучшие рекорды.
- PUZZLES: очистить поле; фигуры не падают сами, уровни открываются по порядку.
  - Подсказка: одна на уровень навсегда (`pocket-tetris-hints`). Кнопка ПОДСКАЗКА на консоли между ЗАПАС и СТАРТ (видна только в головоломках, бледнеет, когда потрачена) и кнопка на экране после неудачи. Уровень начинается заново, клетки для текущей фигуры подсвечиваются, на шаге H просят нажать ЗАПАС. Движок сообщает клетки фиксации в событии `lock`; поставил не туда — подсказка выключается.
  - Фигура не падает сама. Опущенная до опоры, она ставится сама через 30 тиков (0,5 с, `PUZZLE_LOCK_TICKS`); сдвиг и поворот откладывают это, как в обычных режимах, поэтому её можно задвинуть под навес. Новое нажатие ▼ на лежащую фигуру ставит её сразу, удержание ▼ только опускает (`doAction`, флаг `repeat`).
- BATTLE: онлайн 1 на 1 по коду комнаты или ссылке `?room=1234`. Общий seed от сервера; мусорные ряды `ATTACK=[0,0,1,2,4]`, +1 за комбо ≥ 2, дырка в мусоре тоже по seed; скорость растёт каждые 30 с.

Правила битвы, которые не дают остановить время (мусор поднимается только при фиксации фигуры):
- пауза сама снимается через 5 с;
- кто свернул приложение на 15 с и больше, тот проиграл;
- если от соперника 25 с ничего не приходит (доска отправляется ещё и как heartbeat каждые 5 с), засчитывается победа, и сопернику уходит `won`.

Правила уровней выбрать можно только в MARATHON, в остальных режимах они фиксированы, чтобы рекорды друзей были сравнимы. В режимах на время уровень растёт каждые N линий, где N = число минут.
Скорость падения как в современном тетрисе: (0,8 − 0,007 × уровень)^уровень секунд на клетку, заранее посчитанная в таблицу `GRAVITY`. Уровень 0 — 1 с, 5 — 0,26 с, 10 — 0,04 с; с 18 фигура падает мгновенно. Задержка фиксации 15 тиков (0,25 с), с уровня 20 на тик меньше за уровень, до 9.
Механика: мешок из 7 фигур, HOLD, призрак, упрощённые кики (`KICKS`, не SRS), без T-spin, до 15 сбросов задержки фиксации, очистка линий 11 тиков. Очки: 40/100/300/1200 × (уровень+1), комбо, back-to-back за тетрис.
«Поделиться» отправляет PNG-карточку (`drawShareCard`: цвета текущей консоли, итоговое поле, цифры, место за день), если браузер умеет делиться файлами, иначе текст. Карточка рисуется заранее, в момент окончания игры: делиться нужно сразу по нажатию.
Скины консоли (`SKINS`) открываются за достижения. Палитра экрана меняется каждые 5 уровней. Музыка генерируется WebAudio: 3 мелодии из общественного достояния (`TRACKS`).
Управление: экранные кнопки (D-pad, A/B, HOLD, START), свайпы по экрану (тап = поворот, свайп вниз быстро = сброс, вверх = HOLD), клавиатура (`KEYMAP`). Автоповтор (DAS/ARR) живёт в интерфейсе; движок получает уже отдельные нажатия.

## Договорённости

- Никаких внешних запросов, CDN и зависимостей: всё лежит локально, CSP строгий. Новый адрес для `fetch`/`EventSource` нужно добавить в `connect-src` в `index.html`.
- Локальный запуск: статический сервер строго на `http://127.0.0.1:8093` (не `localhost`: от hostname зависит `SERVER_URL`, и этот origin есть в `ALLOWED_ORIGINS`), сервер `node server/server.js` на 8094. В CSP нет `http://127.0.0.1:8094`; для локальной проверки отдавать `index.html` с этим адресом, добавленным в `connect-src` на лету, а не править файл. Лимиты сервера считаются по адресу, поэтому между тестовыми прогонами его перезапускать.
- Проверка:
  - Детерминизм движка проверяется в Node: бот играет с `record:true`, `replay()` записи должен дать ту же игру.
  - В браузере: Chrome установлен, `playwright-core` ставить во временную папку, не в проект.
  - Chrome на этой машине русский, поэтому тесты, которые читают надписи, ставят `pocket-tetris-lang`.
  - Головоломки проверяются прогоном `--solutions` в настоящей игре. После сброса фигуры ждать ~250 мс: во время очистки линий игра не принимает нажатия.
  - Главная проверка таблицы дня: счёт, который видел игрок, совпадает со счётом, который сервер получил из записи.
- `localStorage` только через `readStore`/`writeStore`/`removeStore` (они в try/catch), ключи с префиксом `pocket-tetris-`.
  - Если правила меняются и старые рекорды становятся несравнимы, рекорды получают новые ключи (сейчас `pocket-tetris-rec2-*` и `pocket-tetris-daily-rec2-<день>`, запись лучшей партии дня в `…-replay`). Старые ключи перечисляются в `OLD_RECORD_KEYS` и удаляются при запуске. Цвета консоли и прогресс головоломок при этом не трогаются.
  - Имя для таблицы дня лежит в `pocket-tetris-name`, id игрока (он же код восстановления) — в `pocket-tetris-player`.
- Два языка, русский и английский. Любой видимый текст (и `aria-label`) берётся через `t(key, …)` из словаря `TEXT` в `app.js`; неизменяемые тексты в `index.html` помечены `data-t` / `data-ta` и расставляются в `applyLang()`. Новый текст — сразу в оба словаря. Язык: сохранённый `pocket-tetris-lang`, иначе русский, если язык телефона из региона (ru, kk, uk…), иначе английский; кнопка RU/EN рядом со звуком.
  - Русский текст должен быть понятным: без игрового жаргона (СЕРИЯ, а не КОМБО; ЗАПАС, а не HOLD). Надписи заглавными, пиксельный шрифт; в нём латиница и русская кириллица, казахских букв нет (кроме І, Ұ). Место узкое: подписи боковых панелей до ~10 знаков, кнопки-пилюли до ~7.
- Комментарии в коде по-английски, объясняют «почему». Стиль `app.js` плотный, в духе ES5, его нужно сохранять.
- Сообщения коммитов по-русски: заголовок одной строкой о том, что изменилось для игрока, в теле при необходимости список изменений. В git не настроено имя автора: коммитить с `-c user.name="Мади" -c user.email="madik2005.04.22@gmail.com"`, как в истории.
- Тестов и линтера в репозитории нет.
